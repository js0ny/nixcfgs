# AGENTS.md

## Comments

- If a module requires manual setup outside Nix evaluation or activation (not declarative), mark it with a comment in this format: `# [Human Intervention] xxxxxx`.
  - Human Intervention: For example, some setup should be done using GUI
  - Not Human Intervention: Manually setup a sops/age secret, which is declarative and reproducible once setup, this is considered as a prerequisite for nix evaluation or activation.

```nix
# [Human Intervention] required on first setup
/*
  sudo garage layout status
  sudo garage layout assign <ID> -z dc1 -c 50G
  sudo garage layout show
  sudo garage layout apply --version 1
*/
```

- When a freeform `settings` attribute maps directly to an upstream configuration schema (for example, `services.some-service.settings`), place a comment containing the upstream configuration documentation URL immediately above `settings = { ... };`.

```nix
# https://opencode.ai/docs/config/
programs.opencode.settings = { ... };
```

- When writing multi-line strings in Nix, use the `/* lang */` comment hint syntax for syntax highlighting:

```nix
extraConfig = /* nginx */ ''
  proxy_buffering off;
  proxy_cache off;
  proxy_read_timeout 1800;
  proxy_send_timeout 1800;
  proxy_connect_timeout 1800;
  add_header X-Accel-Buffering "no" always;
'';
```

## Coding styles

- Prefer structured values and existing helper functions over manually encoded strings when they improve readability and produce focused diffs. For example, use `lib.concatStringsSep ","` with a list instead of a long comma-separated string, or `lib.concatStringsSep "\n"` instead of manually joining lines.
- Put each item of a multi-item configuration list on its own line so additions, removals, and reordering are easy to review. Preserve the generated value and item order when refactoring.

```nix
LyricsPriority = lib.concatStringsSep "," [
  ".ttml"
  ".lrc"
  "embedded"
];
```

- Unless shell functionality is required, keep program runner interpreter-less

```nix
# Good
ExecStart = lib.escapeShellArgs [
  (lib.getExe' config.services.fail2ban.package "fail2ban-client")
  "reload"
  "jellyfin"
];
# Bad
script = /* bash */ ''
  ${lib.getExe' config.services.fail2ban.package "fail2ban-client"} reload jellyfin
'';
```

- When adding packages from non-nixpkgs flake inputs, for example, `inputs.glide-browser`, use the package directly from the input instead of adding it into overlay.

```nix
# Good
home.packages = [ inputs.glide-browser.packages.${pkgs.stdenv.hostPlatform.system}.default ];
```

## Scripting

### Choosing a scripting language

- Use Bash for simple wrappers and core modules, such as `export ABC=DEF; exec npx @abc/def "$@"`.
- Use Nushell for complex scripts that frequently invoke external commands or operate on the filesystem. Nix attrsets (or lists of attrsets) can be serialised with `builtins.toJSON` and embedded directly in Nushell, as in `let m = ${builtins.toJSON pluginManifest}`.
- Use Python when frequent external command invocation is not needed, but a powerful standard library is.
- Use Node.js with TypeScript when the primary task is JSON processing or web operations; this is an uncommon choice.
- Never use a language that is not mentioned above (for example `perl`), unless a library is only available for that language (for example `taglib` in C++), discuss with the user at that case.

### Nix-generated scripts

- In shell snippets generated by Nix, prefer `lib.getExe`/`lib.getExe'` for binaries (for example `lib.getExe pkgs.socat`) instead of hardcoded store paths like `${pkgs.socat}/bin/socat`.

```nix
text = /* bash */ ''
  ${lib.getExe' pkgs.coreutils "ls"} /etc # for packages with multiple binaries, specify the binary name.
  ${lib.getExe pkgs.uv} # yields `uv` instead of `uvx` since `uv` is meta.mainProgram.
'';
```

## Writing config for a service or a program

- Prefer config file to environment variable, environment variable should only be used when
  - There is no equivalent key in the config file
  - The variable is a secret, and the program did not offer a way to inject the secret
- When authoring a systemd service, you may mix the config file and environment variable.
- If the upstream provides a json `$schema`, define it in the config file.

```nix
xdg.configFile."claude/ccusage.json".text = builtins.toJSON { ... };
```

- If reverse-proxy is used, prefer unix socket to port

```nix
services.nginx.virtualHosts.${url}.locations."/" = {
  proxyPass = "http://unix:${socketPath}:/";
  proxyWebsockets = true;
};
```
